# NTFS4Mac 0.1.0 (preview)

By **Vahid Zekic** · https://github.com/vahidzekic/ntfs4mac

First public build of NTFS4Mac: read-write NTFS for macOS in user space,
built on Apple's FSKit and libntfs-3g 2022.10.3.

> **Preview software.** Tested on an Intel Mac with macOS 26.5 using RAM disks
> and disk images. Back up your data before writing to an NTFS disk, and do
> not write to the disk of a hibernated Windows (disable Fast Startup).

## What works

- Mount NTFS volumes read-write through FSKit (no kernel extension, no macFUSE)
- Create, read, write, rename, delete files and folders; symlinks; hard links
- **Format as NTFS from Disk Utility** (Erase › Format › NTFS) and with
  `diskutil eraseDisk NTFS4Mac <name> GPT /dev/diskX`
- Volume shows in Finder as "Windows NT File System (NTFS)"
- Hibernated / Fast Startup volumes fall back to read-only

## Install

1. Download `NTFS4Mac-0.1.0-intel.pkg` (Intel Macs) and open it.
2. Enable the extension: **System Settings › General › Login Items &
   Extensions › By Category › File System Extensions (ⓘ) › NTFS (ntfs4mac)**.
   The switch in the "By App" view does not work on macOS 26.
3. Reconnect your NTFS disk, or format one in Disk Utility.

Requires macOS 15.4 or later (15.6+ recommended). This build is for **Intel
Macs** (x86_64), the platform it was tested on. Apple Silicon users can build
from source (`scripts/make-release.sh` builds universal by default).

## Known limitations

- No full chkdsk/repair; repair a corrupted volume in Windows.
- Apple's built-in read-only NTFS driver can win the automount race; unmount
  and mount again (`mount -F -t ntfs4mac …`) if a disk shows as read-only.
- Remounting the same device immediately after unmounting can fail with
  "Invalid argument"; wait a few seconds.
- No extended attributes / alternate data streams, no POSIX ownership mapping.
